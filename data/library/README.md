# 固定解牌库

按「牌名 + 正逆位 + 主题 + 牌位」读一段。一共 5772 格，空字符串 = 还没写。开发期没写的格页面显示「【开发期缺失】牌名 正逆 · 主题 · 牌位」，并记进 `missingLog()`，5772 格全写完之前不正式开放。

## 普通牌位（4992 格）

文件：`normal/majors.json`、`normal/wands.json`、`normal/cups.json`、`normal/swords.json`、`normal/pents.json`（一个花色一个文件，大牌单独一个）。

```
{
  "major_00": {
    "_name": "愚人",                ← 只是给人看的，程序不读
    "up":  { "life": { "single": "", "day": "", "week_main": "", "week_caution": "", "week_action": "", "past": "", "present": "", "future": "" },
             "love":  { ...同上八个牌位... },
             "work":  { ... },
             "self":  { ... } },
    "rev": { ...跟 up 一样... }
  },
  ...
}
```

- 正逆位：`up` 正位 / `rev` 逆位
- 主题：`life` 日常 / `love` 感情 / `work` 事业 / `self` 自我
- 牌位：`single` 单张 / `day` 每日 / `week_main` 本周主线 / `week_caution` 需要注意 / `week_action` 行动建议 / `past` 过去 / `present` 现在 / `future` 未来

78 × 2 × 4 × 8 = 4992。

## 关系牌阵（780 格）

文件：`relation.json`。关系牌阵不叠主题，只按牌位。

```
{
  "major_00": {
    "_name": "愚人",
    "up":  { "me": "", "him": "", "between": "", "block": "", "toward": "" },
    "rev": { "me": "", "him": "", "between": "", "block": "", "toward": "" }
  },
  ...
}
```

- 牌位：`me` 我 / `him` ta / `between` 我们之间 / `block` 阻碍 / `toward` 走向

78 × 2 × 5 = 780。

## 牌阵怎么对到牌位

- 单张牌阵：问题是「每日一牌」→ `day`；别的问题 → `single`
- 三张牌阵：`past` / `present` / `future`
- 本周牌阵：三张，本周主线 → `week_main`（这一周的核心状态），需要注意 → `week_caution`（可能遇到的阻碍或风险），行动建议 → `week_action`（这一周适合怎么做）
- 关系牌阵：`me` / `him` / `between` / `block` / `toward`

主题由问题里的词猜（`js/reading.js` 的 `detectCategory`），结果页也能手动切。

## 写文案的约定

- 一格一段，两到四句，说这张牌在这个牌位、这个主题下的意思，别复述牌名。
- 牌位的时态要对：过去位谈此前可能出现的模式，现在位谈眼下值得观察的状态，未来位谈照当前走法可能形成的趋势；每日说今天，本周三个位说这周。
- 本周三个位各管各的：主线说状态，需要注意说阻碍和风险，行动建议说怎么做。
- 主题词不要越界：感情格不谈工作，事业格不谈恋爱。
- 不认识提问者，不猜背景，不鸡汤。
- 可以明确解释牌的象征主题，但不能把牌义直接写成用户已经发生的事实，也不能承诺结果。优先用「这张牌指向」「这一周的主题是」「更值得观察的是」保持力度，不要机械堆叠「可能」。
- 过去、现在、每日、本周和未来都不自动获得事实性；没有用户背景时，具体事件要写成假设或观察方向。后文带「如果」也不能替前文的绝对断言兜底。
- `ta` 牌位只描述可能呈现的状态或可观察表现，不确定 ta 的隐藏动机；涉及双方真实想法时，提醒需要沟通确认。
- 行动建议可以具体，但不凭空规定期限，不替用户做分手、离职、投资等重大决定，不使用恐吓、羞辱或宿命式表达。
- 一段通常只需一个条件或限定；其余句子可以直接解释牌义，避免每句话都塞「可能」而失去自然口吻。
- 固定解读只使用当前格文案，不拼接 `js/data/text.js` 的旧通用建议；需要行动内容时，直接写进对应格，尤其是 `week_action`。
- 第二人称写「你」，另一半一律写小写「ta」，不写「他 / 她 / 对方」。
- 改完跑一遍 `check`，JSON 写坏了整个文件都读不进去。
